# 02-03 消息与公告

## 1. 功能说明

- **消息**：系统发给个人的通知（审批结果、任务完成、提醒、系统通知），站内显示，可选同时发邮件。
- **公告**：管理员发布给全员或部分部门的通知（放假安排、制度），首页展示，登录后未读的重要公告弹窗提示。

- 优先级：消息 P0；公告 P1

## 3. 页面

### 3.1 消息中心（`/workbench/message`）

左侧类型筛选（全部、审批结果、任务、提醒、系统，显示未读数）；右侧列表：未读圆点、标题、内容摘要、时间；点击展开详情并标记已读，有 route 时显示 [查看]。工具栏：[全部已读]、[删除已读]。
头部铃铛下拉中也显示最近 5 条未读消息（与待办分两个页签）。

### 3.2 公告管理（`/workbench/notice`，`wb:notice:manage`）

列表：标题、范围、重要、发布时间、过期时间、阅读人数/应读人数、状态、操作（编辑、发布、撤回、查看阅读情况）。
编辑：标题*、内容*（富文本编辑器）、范围*、部门、重要、发布时间*（默认立即）、过期时间、附件。

## 4. 业务规则

| 编号 | 规则 |
|---|---|
| WB-MSG-R01 | 邮件发送异步执行，失败重试 3 次（间隔 1、5、15 分钟），仍失败记录日志，不影响站内消息 |
| WB-MSG-R02 | 用户未配置邮箱时不发邮件 |
| WB-MSG-R03 | 消息保留 `wb.message.retention-days` 天 |
| WB-NTC-R01 | 公告富文本过滤脚本、事件属性、外部 iframe |
| WB-NTC-R02 | 重要公告：用户登录后若存在已发布、未过期、未读的重要公告，弹窗显示（可“我已阅读”），同一公告只弹一次 |

## 5. 接口

`GET /workbench/messages?type=&read=`、`GET /workbench/messages/unread-count`、`POST /workbench/messages/{id}/read`、`POST /workbench/messages/read-all`、`DELETE /workbench/messages/read`；`/workbench/notices`（CRUD、publish、withdraw、readers）、`GET /workbench/notices/active`、`POST /workbench/notices/{id}/read`。

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| WB-MSG-T01 | 订单被驳回 | — | 发起人收到“审批结果”消息，点击跳转订单 |
| WB-MSG-T02 | 发布重要公告 | 用户登录 | 弹窗显示公告；点“我已阅读”后不再弹出 |
| WB-MSG-T03 | 公告内容含 `<script>` | 保存 | 脚本被过滤 |
