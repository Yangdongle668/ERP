# 02-02 待办与审批

## 1. 功能说明

集中显示用户需要处理的事项：审批任务（来自审批流）和业务任务（待检验、待入库、待派工、催料、ECN 执行确认等），以及用户已处理的审批和自己发起的审批。

- 优先级：P0

## 2. 数据表

### wb_todo 待办

| 字段 | 类型 | 说明 |
|---|---|---|
| todo_key | str(128) | 业务唯一键（与 user_id 组合唯一） |
| user_id | id | 处理人 |
| category | enum(APPROVAL/TASK) | 审批 / 任务 |
| biz_type | str(64) | 单据类型 |
| biz_id | id | |
| biz_no | str(64) | |
| title | str(256) | |
| route | str(256) | 点击跳转的前端路由 |
| priority | enum(HIGH/NORMAL/LOW) | |
| due_time | datetime | 期限（可空） |
| todo_status | enum(PENDING/DONE/CANCELED) | |
| created_at / done_at | datetime | |

唯一：`uk_key_user(todo_key, user_id)`（事件重复投递时幂等）。

## 3. 页面：待办（路由 `/workbench/todo`，三个页签）

### 3.1 我的待办

- 查询：类别（全部/审批/任务）、单据类型、关键字（标题/单号）、创建时间、仅超期。
- 列：类别标签、单据类型、单号、标题、优先级（高红色）、创建时间、期限（已超期红色，显示超期时长）、停留时长、操作（[处理]：跳转 route；审批类另有 [通过]、[驳回] 快捷按钮）。
- 批量操作：勾选审批类待办 → [批量通过]（统一意见，调用审批流批量接口，逐条返回结果；有需要填写业务内容的审批节点不支持批量，会被跳过并提示）。
- 排序：优先级 → 期限 → 创建时间。

### 3.2 我已处理

审批任务（来自审批流 `GET /system/workflow/tasks/my?status=DONE`）：单据类型、单号、标题、我的处理结果（通过/驳回/转交）、意见、处理时间、实例当前状态。任务类待办的已完成记录（最近 90 天）。

### 3.3 我发起的

来自审批流 `GET /system/workflow/instances/my`：单据类型、单号、标题、发起时间、当前节点、当前处理人、状态（审批中/已通过/已驳回/已撤回）；审批中的可 [撤回]。

## 4. 待办来源一览

| 来源模块 | 待办 | todo_key | 完成条件 |
|---|---|---|---|
| 系统管理·审批流 | 审批任务 | `WF_TASK:{taskId}` | 任务处理/取消 |
| 品质 | 待检验单 | `QC_INSP:{id}` → 检验员角色用户 | 判定 |
| 仓库 | 待确认入库/出库/调拨 | `INV_IN:{id}` 等 → 该仓库操作人员 | 确认/作废 |
| 生产 | 待派工、待领料发料提醒 | `MFG_*` | 相应动作完成 |
| 研发工程 | ECN 执行确认、样品寄出、物料待启用 | `ENG_ECN_TASK:{id}` 等 | 完成 |
| PMC | 催料（给采购员）、订单减量评估（给计划员） | `PMC_SHORT:{materialId}:{date}` | 手工标记完成 |
| 资材 | 入库被退回处理、交期到期 | `PUR_*` | 处理 |
| CRM | 跟进提醒 | `CRM_FU:{id}` | 新增跟进 |
| 销售 | 交期风险沟通 | `SAL_RISK:{lineId}` | 处理 |
| 财务 | 待确认应收/应付（自动确认关闭时） | `FIN_*` | 确认 |

“手工标记完成”类待办在列表中提供 [标记完成] 按钮。

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| WB-TODO-R01 | 头部铃铛角标 = 我的待办（PENDING）数量，每 `wb.todo.poll-seconds` 秒刷新 |
| WB-TODO-R02 | 待办的创建/完成由事件驱动；同一 todo_key 重复创建时更新标题和期限，不新增 |
| WB-TODO-R03 | 用户停用时其待办由来源模块处理（审批流转交）；其他任务类待办转给部门负责人（工作台监听用户停用事件执行） |
| WB-TODO-R04 | 每天 02:00 对账：对仍为 PENDING 的审批待办，查询审批流任务状态，不一致时修正（防事件丢失） |
| WB-TODO-R05 | 已完成待办保留 `wb.todo.retention-days` 天 |

## 6. 接口

`GET /workbench/todos?status=&category=`、`GET /workbench/todos/count`、`POST /workbench/todos/{id}/done`（手工完成类）、`POST /workbench/todos/batch-approve`（转调审批流）。

## 7. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| WB-TODO-T01 | 提交采购订单需审批 | — | 审批人待办出现，角标 +1 |
| WB-TODO-T02 | 审批人在订单详情页通过 | — | 待办消失，角标 −1；“我已处理”出现记录 |
| WB-TODO-T03 | 5 条审批待办 | 批量通过 | 逐条执行，全部成功或列出失败原因 |
| WB-TODO-T04 | 发起人 | “我发起的”撤回 | 实例撤回，审批人待办消失 |
| WB-TODO-T05 | IQC 单判定 | — | 检验员的待检待办消失 |
