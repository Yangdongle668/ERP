# 01-01 组织架构

## 1. 功能说明

维护公司与部门的树形结构。组织是数据权限（本公司、本部门及下级）、审批人（部门负责人）、单据归属（`org_id`、`dept_id`）的基础。

- 使用者：系统管理员
- 优先级：P0

**组织类型**

| 类型 | 编码 | 说明 |
|---|---|---|
| 公司 | COMPANY | 法人或独立核算单位。单据的 `org_id` 指向公司 |
| 部门 | DEPT | 公司下的部门、车间、科室、班组 |

层级约束：根节点必须是公司；公司下可以有公司（子公司）或部门；部门下只能有部门。最多 8 级。

| name_en | str(128) | 否 | | 英文名称（公司用于英文单据抬头） |

## 4. 状态与流转

启用 ⇄ 停用。停用的组织：不能被选为新用户的部门、不能在新单据中选择；已有数据不受影响。

## 5. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| SYS-ORG-R01 | 保存 | 根节点必须是公司；部门下不能建公司 | `部门下不能创建公司` / `顶级组织必须是公司` |
| SYS-ORG-R02 | 保存 | 上级不能是自己或自己的下级 | `上级组织不能是自己或自己的下级` |
| SYS-ORG-R03 | 保存 | 层级不超过 8 级 | `组织层级不能超过 8 级` |
| SYS-ORG-R04 | 保存 | 编码全局唯一（不区分大小写） | `组织编码「{code}」已存在` |
| SYS-ORG-R05 | 停用 | 存在启用状态的下级组织或启用状态的用户（主部门）时不允许停用 | `请先停用下级组织` / `该部门下还有 {n} 个启用的用户，请先调整用户部门或停用用户` |
| SYS-ORG-R06 | 启用 | 上级组织为停用时不允许启用 | `上级组织已停用，请先启用上级组织` |
| SYS-ORG-R07 | 删除 | 存在下级、存在用户（含停用、含兼职）、或被业务数据引用（组织 ID 被任何业务表引用，通过 `OrgReferenceChecker` 扩展点由各模块提供检查）时不允许删除 | `该组织存在下级组织，不能删除` / `该组织下存在用户，不能删除` / `该组织已被业务数据使用，只能停用` |
| SYS-ORG-R08 | 保存 | 同一上级下名称不重复 | `同一上级下已存在名称为「{name}」的组织` |
| SYS-ORG-R09 | 修改上级 | 修改上级时同步更新自身及全部下级的 `path`、`level`，在同一事务内完成 | — |
| SYS-ORG-R10 | 保存 | 至少保留一个启用的根公司 | `至少需要保留一个启用的公司` |

组织变更后清除组织缓存和所有用户的数据范围缓存。

## 6. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /system/orgs/tree | `system:org:query` | 完整树（含停用），参数 `keyword`、`status` |
| GET | /system/orgs/simple-tree | 登录即可 | 仅启用节点的精简树（id、parentId、name、orgType），供 OrgTreeSelect 使用 |
| GET | /system/orgs/{id} | `system:org:query` | 详情 |
| POST | /system/orgs | `system:org:create` | 新建 |
| PUT | /system/orgs/{id} | `system:org:update` | 修改（带 version） |
| POST | /system/orgs/{id}/enable | `system:org:update` | 启用 |
| POST | /system/orgs/{id}/disable | `system:org:update` | 停用 |
| DELETE | /system/orgs/{id} | `system:org:delete` | 删除 |

## 7. 与其他模块的交互

- 提供 `OrgApi`（见总览）。
- 扩展点 `OrgReferenceChecker`：业务模块实现 `boolean isReferenced(Long orgId)`，删除组织时逐一调用。

## 8. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| SYS-ORG-T01 | 存在根公司 HQ | 在 HQ 下新增部门“采购部” | 保存成功，树中 HQ 下显示采购部，排序为同级最大值 + 10 |
| SYS-ORG-T02 | 采购部为部门 | 在采购部下新增，类型选公司 | 类型单选只能为部门；接口直接提交公司类型时返回“部门下不能创建公司” |
| SYS-ORG-T03 | A 下有 B，B 下有 C | 编辑 A，上级选 C | 提示“上级组织不能是自己或自己的下级” |
| SYS-ORG-T04 | 已存在编码 PUR | 新建编码 pur | 提示“组织编码「PUR」已存在” |
| SYS-ORG-T05 | 采购部有 2 个启用用户 | 停用采购部 | 提示“该部门下还有 2 个启用的用户…” |
| SYS-ORG-T06 | 采购部下有子部门，将采购部移动到另一公司下 | 保存 | 采购部及子部门的 path、level 全部正确更新；按“本部门及下级”数据范围的用户查询结果随之变化 |
| SYS-ORG-T07 | 部门被采购订单引用 | 删除 | 提示“该组织已被业务数据使用，只能停用” |
| SYS-ORG-T08 | 输入关键字“采购” | 查询 | 显示采购部及其所有上级节点，其他分支隐藏 |
