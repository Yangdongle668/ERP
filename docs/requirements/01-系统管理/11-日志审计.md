# 01-11 日志审计

## 1. 功能说明

记录并查询三类日志：

| 日志 | 记录什么 | 谁写入 |
|---|---|---|
| 登录日志 | 登录、登出、刷新令牌失败、锁定 | 系统管理模块 |
| 操作日志 | 所有写操作接口（POST/PUT/DELETE）的调用 | 框架自动记录（Controller 方法标注 `@OperLog(module, action)`，未标注的写接口按“模块 + 接口路径”记录） |
| 单据操作日志 | 单据状态变更：提交、审核、反审核、关闭、作废等，含原因 | 业务模块调用 `DocLogApi.record(...)` |

- 使用者：系统管理员（全部）；单据操作日志在各单据详情页“操作日志”页签展示
- 优先级：P0
- 日志只增不改，任何人（包括超级管理员）都不能在界面上修改或删除，只能按保留期自动清理。

## 2. 数据表

### sys_login_log 登录日志（技术表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | |
| username | str(32) | 输入的用户名（用户不存在也记录） |
| user_id | id | 用户存在时 |
| type | enum(LOGIN/LOGOUT/REFRESH) | |
| result | enum(SUCCESS/BAD_CREDENTIALS/LOCKED/DISABLED/CAPTCHA_ERROR/EXPIRED) | |
| ip | str(64) | 客户端 IP（优先取 `X-Forwarded-For` 第一个） |
| user_agent | str(512) | |
| browser / os | str(64) | 由 UA 解析 |
| created_at | datetime | |

索引：`idx_created(created_at)`、`idx_user(user_id, created_at)`。

### sys_oper_log 操作日志（技术表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | |
| trace_id | str(64) | 请求追踪号 |
| module_code | str(32) | 模块 |
| action | str(64) | 操作名称，如“新建物料” |
| method | str(8) | HTTP 方法 |
| path | str(256) | 请求路径 |
| params | text | 请求参数 JSON，截断至 4000 字符；**敏感字段脱敏**：名称包含 password、secret、token 的字段值替换为 `******` |
| result | enum(SUCCESS/BIZ_ERROR/SYSTEM_ERROR) | |
| error_code | int | |
| error_msg | str(512) | |
| duration_ms | int | 耗时 |
| user_id / username / real_name | | 操作人 |
| ip | str(64) | |
| created_at | datetime | |

索引：`idx_created(created_at)`、`idx_user(user_id, created_at)`、`idx_trace(trace_id)`。按月分区（MySQL）。

写入方式：异步（线程池 + 有界队列，队列满时丢弃并记录错误日志），**不影响业务请求的耗时和成功与否**。

## 3. 页面

### 3.1 日志审计（T1，两个页签）

路由 `/system/log`，权限 `system:log:query`。

**登录日志页签**

- 查询条件：用户名（模糊）、结果（下拉）、IP（前缀）、时间（日期时间范围，默认今天）。
- 列：时间（160）、用户名（120）、姓名（100）、类型（80）、结果（100，成功绿色、其他红色标签）、IP（130）、浏览器（120）、操作系统（120）。
- 按钮：导出（`system:log:export`）。

**操作日志页签**

- 查询条件：操作人（UserSelect）、模块（下拉）、操作（模糊）、结果、追踪号（精确）、时间（默认今天）。
- 列：时间（160）、操作人（100）、模块（90）、操作（160）、结果（90）、耗时（80，右，>3000ms 橙色）、IP（130）、追踪号（120，可复制）、操作（[详情]）。
- 详情抽屉：显示全部字段，参数以格式化 JSON 显示。
- 按钮：导出。

### 3.2 单据详情页“操作日志”页签（`OperationLogTable` 组件）

列：时间、操作人、动作、状态变化（“草稿 → 待审批”，用 StatusTag）、原因。按时间正序。

## 4. 业务规则

| 编号 | 触发 | 规则 |
|---|---|---|
| SYS-LOG-R01 | 定时（每天 02:00） | 删除超过保留期的登录日志、操作日志（每批 5000 条，避免长事务）；单据操作日志永久保留 |
| SYS-LOG-R02 | 写操作日志 | 失败不影响业务请求；日志系统异常只记录到应用日志文件 |
| SYS-LOG-R03 | 脱敏 | 参数中的密码类字段必须脱敏；文件上传类接口不记录文件内容，只记录文件名和大小 |
| SYS-LOG-R04 | 查询 | 查询时间范围最大 3 个月，超过提示 `查询时间范围不能超过 3 个月` |

## 5. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /system/login-logs | `system:log:query` | 分页 |
| GET | /system/oper-logs | `system:log:query` | 分页 |
| GET | /system/oper-logs/{id} | `system:log:query` | 详情 |
| GET | /system/login-logs/export、/oper-logs/export | `system:log:export` | 导出 |
| GET | /system/doc-logs?bizType=&bizId= | 登录即可（业务详情页使用） | 单据操作日志 |

Java API：`DocLogApi.record(bizType, bizId, bizNo, action, actionName, fromStatus, toStatus, reason)`。

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| SYS-LOG-T01 | — | 用错误密码登录 | 登录日志记录一条 BAD_CREDENTIALS，含 IP 和浏览器 |
| SYS-LOG-T02 | — | 修改自己的密码 | 操作日志的参数中密码字段显示 `******` |
| SYS-LOG-T03 | 某请求失败并提示追踪号 | 在操作日志中按追踪号查询 | 找到该请求，结果为 SYSTEM_ERROR |
| SYS-LOG-T04 | 销售订单经过提交、审核、关闭 | 打开订单“操作日志”页签 | 3 条记录，状态变化和关闭原因正确 |
| SYS-LOG-T05 | 查询时间范围选 4 个月 | 查询 | 提示“查询时间范围不能超过 3 个月” |
