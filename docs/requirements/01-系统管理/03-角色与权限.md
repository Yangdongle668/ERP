# 01-03 角色与权限

## 1. 功能说明

角色是权限的集合。给角色授予**功能权限**（菜单、按钮、接口）和**数据范围**，再把角色分配给用户。一个用户可以有多个角色，权限取并集。

- 使用者：系统管理员
- 优先级：P0

### 1.1 权限点

权限点是一个字符串标识，格式 `模块:资源:动作`，例如 `sales:order:approve`。

- **来源**：各业务模块通过 `PermissionDefinition` 声明（见总览第 5 节），启动时同步到 `sys_permission`。管理员不能在界面上新建权限点，只能分配。
- **层级**：模块 → 分组（通常对应一个菜单页面）→ 权限点。分组中类型为“菜单”的权限点（通常是 `xxx:query`）控制菜单是否可见。
- **类型**：
  - `MENU` 菜单：可见该页面（同时拥有查询接口权限）
  - `BUTTON` 操作：按钮 + 对应接口
  - `FIELD` 字段：查看敏感字段，如 `pur:price:view`（采购价）、`sales:quotation:cost`（成本与毛利）、`inv:stock:cost`（库存成本）
- **依赖**：权限点可声明依赖（如 `sales:order:approve` 依赖 `sales:order:query`）。授权界面勾选某权限点时自动勾选其依赖。

### 1.2 数据范围

| 数据范围 | 编码 | 含义（对业务单据的 `dept_id` / `owner_id` 过滤） |
|---|---|---|
| 全部 | ALL | 不限制 |
| 本公司 | COMPANY | 单据 `org_id` = 用户所属公司 |
| 本部门及下级 | DEPT_AND_CHILD | 单据 `dept_id` 在用户主部门、兼职部门及它们全部下级中 |
| 本部门 | DEPT | 单据 `dept_id` 在用户主部门、兼职部门中 |
| 仅本人 | SELF | 单据 `owner_id` = 用户（或 `created_by` = 用户，按单据定义） |
| 自定义 | CUSTOM | 单据 `dept_id` 在角色指定的部门列表中 |

- 用户有多个角色时取**最大范围**（并集）。
- 主数据（物料、计量单位等）默认不受数据范围限制；客户、供应商按“负责人”字段受限（在 CRM、资材文档中定义）。
- 数据范围由框架层统一拼接查询条件：业务 Mapper 查询方法标注 `@DataScope(deptColumn = "dept_id", userColumn = "owner_id")` 即可，业务代码不手写条件（框架改动）。
- 超级管理员不受数据范围限制。

## 2. 数据表

### sys_role 角色（已有表，补充字段）

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| code | str(32) | 是 | | 角色编码，唯一，大写字母数字下划线 |
| name | str(32) | 是 | | 角色名称，唯一 |
| data_scope | enum(ALL/COMPANY/DEPT_AND_CHILD/DEPT/SELF/CUSTOM) | 是 | SELF | 数据范围 |
| is_builtin | bool | 是 | 0 | 内置角色（SUPER_ADMIN）不可编辑权限、不可删除、不可停用 |
| sort | int | 是 | 0 | 排序 |
| status | enum(ENABLED/DISABLED) | 是 | ENABLED | |
| remark | str(256) | 否 | | |

### sys_role_permission 角色权限（已有，技术表）

`role_id`、`permission`。超级管理员角色的权限为 `*`。

### sys_role_data_dept 自定义数据范围（技术表）

`role_id`、`dept_id`，主键两列。仅 `data_scope = CUSTOM` 时有数据。

### sys_permission 权限点目录（技术表，由声明同步）

| 字段 | 类型 | 说明 |
|---|---|---|
| code | str(128) 主键 | 权限标识 |
| module_code | str(32) | 模块编码 |
| group_code | str(64) | 分组编码 |
| group_name | str(64) | 分组名称（通常为菜单名） |
| name | str(64) | 权限名称，如“审核” |
| type | enum(MENU/BUTTON/FIELD) | |
| depends_on | str(512) | 依赖的权限点，逗号分隔 |
| sort | int | 在分组内的排序 |
| active | bool | 代码中已删除的权限点置为 0，授权界面不显示，但已有授权记录保留 |

### 3.3 功能权限抽屉（宽 720px）

```
┌ 功能权限 - 采购员 ──────────────────────────────────────── [×] ┐
│ [🔍 搜索权限]                              [全部展开] [全部收起] │
│ ☑ 资材                                                          │
│   ☑ 供应商        ☑ 查看  ☑ 新建  ☑ 编辑  ☐ 停用  ☐ 导出          │
│   ☑ 采购订单      ☑ 查看  ☑ 新建  ☑ 编辑  ☑ 提交  ☐ 审核  ☐ 关闭   │
│   ☐ 采购价格      ☐ 查看采购价（字段）                             │
│ ☐ 仓库                                                          │
│   ...                                                           │
│                                                   [取消] [保存] │
└─────────────────────────────────────────────────────────────────┘
```

- 每个分组一行：分组名 + 该分组的权限点复选框（菜单类型排第一）。
- 勾选任一权限点时自动勾选其依赖（通常是查看）；取消“查看”时同时取消该分组其他权限点（提示“取消查看将同时取消该页面的其他权限”）。
- 模块、分组复选框支持半选状态。
- 搜索：按权限名称或分组名称过滤。
- 保存：整体覆盖该角色的权限列表；清除拥有该角色的所有用户的权限缓存。

### 3.4 角色成员抽屉（宽 720px）

- 列表：用户名、姓名、主部门、状态、[移除] 按钮。
- 顶部 [添加成员]：UserSelect 多选，确定后添加。
- 移除时校验 SYS-USR-R05（用户至少一个角色）：`用户「{name}」只有这一个角色，不能移除`。
- 权限：添加/移除需要 `system:role:update`。

## 4. 状态与流转

启用 ⇄ 停用。停用的角色：拥有该角色的用户不再获得其权限（权限计算时忽略停用角色）；不能分配给新用户。

## 5. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| SYS-ROL-R01 | 保存 | 编码唯一 | `角色编码「{code}」已存在` |
| SYS-ROL-R02 | 保存 | 名称唯一 | `角色名称「{name}」已存在` |
| SYS-ROL-R03 | 修改 | 内置角色不能修改、授权、停用、删除 | `内置角色不能修改` |
| SYS-ROL-R04 | 停用 | 停用后仍需保证每个启用用户至少有一个启用角色；否则列出受影响用户 | `停用后以下用户将没有任何可用角色：{names}，请先为他们分配其他角色` |
| SYS-ROL-R05 | 删除 | 角色下存在用户（含停用用户）时不能删除 | `该角色下还有 {n} 个用户，请先移除` |
| SYS-ROL-R06 | 授权 | 只能授予 `sys_permission` 中存在且 active 的权限点；`*` 只能属于内置超级管理员 | `权限点「{code}」不存在` |
| SYS-ROL-R07 | 授权/成员变更/停用/启用/数据范围变更 | 清除相关用户的登录用户缓存，权限立即生效 | — |

## 7. 与其他模块的交互

- 各模块声明 `PermissionDefinition`，示例：

```java
@Bean
public PermissionDefinition materialPermissions() {
    return PermissionDefinition.group("engineering", "material", "物料")
            .menu("eng:material:query", "查看")
            .button("eng:material:create", "新建")
            .button("eng:material:update", "编辑")
            .button("eng:material:enable", "启用")
            .button("eng:material:disable", "停用")
            .button("eng:material:import", "导入")
            .button("eng:material:export", "导出")
            .field("eng:material:cost", "查看成本");
}
```

- 各模块需求文档“权限点”一节的清单即为该模块需要声明的全部权限点。
- 框架提供 `@DataScope(orgColumn, deptColumn, userColumn)` 注解（加在 Mapper 查询方法上，自动拼接数据范围条件；`DataScopes.ignore()` 临时跳过）与 `SecurityUtils.currentDataScope()`（需要手工拼条件时读取当前用户的数据范围）。

## 8. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| SYS-ROL-T01 | — | 新建角色“采购员”，数据范围“仅本人”，授予采购订单查看/新建/提交 | 采购员登录后只看到资材 → 采购订单菜单，页面上只有新建、提交按钮，没有审核按钮 |
| SYS-ROL-T02 | 采购员 A、B 各建了采购订单 | A 查询采购订单列表 | 只看到自己的订单 |
| SYS-ROL-T03 | A 同时有“采购员（仅本人）”和“采购主管（本部门及下级）” | A 查询 | 看到本部门及下级所有人的订单 |
| SYS-ROL-T04 | 在授权抽屉中 | 勾选“审核”，不勾“查看” | 自动勾选“查看” |
| SYS-ROL-T05 | 用户正在使用系统 | 管理员取消其角色的“新建”权限 | 用户刷新页面后“新建”按钮消失；直接调用接口返回 403 |
| SYS-ROL-T06 | 角色下有 3 个用户 | 删除角色 | 提示“该角色下还有 3 个用户，请先移除” |
| SYS-ROL-T07 | 某用户只有角色 X | 停用 X | 提示停用后该用户将没有可用角色 |
| SYS-ROL-T08 | 仓管员有采购订单查看权限，但无 `pur:price:view` | 查看采购订单 | 单价、金额列显示 `***`，导出中为空 |
| SYS-ROL-T09 | 代码中删除了某权限点并重启 | 打开授权抽屉 | 该权限点不再显示，已有授权记录不报错 |
