# 12-05 付款

## 1. 功能说明

付款流程：采购/应付会计按到期应付发起**付款申请** → 审批 → 出纳按申请执行**付款**（登记付款单）→ 付款自动核销对应应付。预付款（订单未到货先付款）也走付款申请，付款后作为预付，在应付生成后冲销。

- 使用者：应付会计、采购员（可发起）、财务主管、出纳
- 优先级：P0

## 3. 页面

### 3.1 付款申请（T1 / T4 / T5）

列表：单号、类型、供应商、币别、申请金额、已付、计划付款日、状态、申请人、操作。顶部快捷：`待审批`、`待付款`、`本周计划付款`。
新建（T4）：供应商*、类型*、币别*、计划付款日*、收款账户*（供应商银行）、原因；按应付付款时 [选择应付]（该供应商已确认、未付未申请金额 > 0 的应付，按到期日排序，显示到期状态），每行申请金额（默认未付未申请金额）；预付款时选择采购订单*，输入金额（≤ 订单价税合计 − 已预付）。
详情：审批、[付款]（出纳，跳转付款单并带入）、关闭（部分付款后剩余不再支付）、作废（草稿）、打印（付款申请单）。

### 3.2 付款单（T1 / T4）

列表：单号、申请单、供应商、付款账户、付款日期、币别、金额、手续费、状态、出纳。
新建：从付款申请带入，填写付款账户*（同币别）、付款日期*、结算方式*、金额*（≤ 申请未付金额）、手续费、银行流水号、附件（回单）。[确认]：自动核销申请中的应付（按申请行比例分配；预付款记为预付余额）。

### 3.3 预付冲应付

在付款核销页面（与收款核销相同的布局：左预付/付款，右应付），把预付余额核销到该供应商后续应付。

## 4. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| FIN-PAY-R01 | 申请 | 申请金额 ≤ 应付未付未申请金额；同一应付可以分多次申请 | `应付「{no}」可申请金额为 {amt}` |
| FIN-PAY-R02 | 申请 | 未匹配发票的应付：参数允许时可申请（提示“该应付尚未收到发票”），否则阻止（P1 参数，默认允许并提示） | — |
| FIN-PAY-R03 | 付款 | 付款金额 ≤ 申请未付金额；付款账户币别 = 申请币别 | `付款金额超过申请未付金额` |
| FIN-PAY-R04 | 确认付款 | 自动核销：按申请行顺序分配到应付；汇兑差异同收款规则；更新申请已付金额与状态 | — |
| FIN-PAY-R05 | 反确认 | 期间未结账；反核销后回到草稿 | — |
| FIN-PAY-R06 | 预付 | 预付款申请必须关联采购订单；预付累计 ≤ 订单价税合计 | `预付金额超过订单金额` |
| FIN-PAY-R07 | 提醒 | 每周一给应付会计推送本周到期应付清单 | — |

## 5. 接口

`/finance/payment-requests`（CRUD、submit、close、void、print-data）、`GET /finance/payables/payable-candidates?supplierId=`、`/finance/payments`（CRUD、confirm、unconfirm）、`POST /finance/verifications/payment`、`POST /finance/verifications/prepay`。

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| FIN-PAY-T01 | 应付 10,735 | 申请 10,735 → 审批 → 付款 | 应付已付款，申请已付 |
| FIN-PAY-T02 | 应付已申请 10,735 | 再申请 | 提示可申请金额为 0 |
| FIN-PAY-T03 | 预付 30% 订单款 | 付款后到货对账生成应付 | 核销页面可用预付冲应付 |
| FIN-PAY-T04 | 付款 5,000 （申请 10,735） | — | 申请状态部分付款；应付已付 5,000 |
