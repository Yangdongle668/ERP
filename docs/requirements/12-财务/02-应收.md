# 12-02 应收

## 1. 功能说明

应收单记录客户欠款：由出货确认自动生成（蓝字），销售退货退款、客诉赔偿生成红字；也可手工新建“其他应收”。应收单确认后参与收款核销、账龄和信用计算。另提供销项发票登记（开票）。

- 使用者：应收会计
- 优先级：P0

## 2. 数据表

### fin_receivable 应收单（BaseDocDO，编码规则 FIN_RECEIVABLE）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| ar_type | enum(SALES/SALES_RETURN/DISCOUNT/OTHER) | 是 | 销售出货 / 退货（红字）/ 折让（红字）/ 其他 |
| customer_id | id | 是 | |
| source_type / source_id / source_no | | 条件 | 出货单、退货单、客诉单 |
| currency / exchange_rate | | 是 | 出货日期汇率 |
| amount / tax_amount / total_amount | amt | 是 | 原币，红字为负数 |
| total_amount_base | amt | 是 | 本位币 |
| biz_date | date | 是 | 业务日期（出货日期），决定会计期间 |
| due_date | date | 否 | 到期日（按订单付款条件计算，多个节点时取最早未收节点；账龄按此计算） |
| verified_amount | amt | 是 | 已核销（原币） |
| invoiced_amount | amt | 是 | 已开票（原币） |
| ar_status | enum(DRAFT/CONFIRMED/VOIDED) | 是 | 草稿 / 已确认 / 已作废 |
| voucher_id | id | 否 | |

**未核销金额** = total_amount − verified_amount。

### fin_receivable_line

`order_id`、`order_line_id`、`source_line_id`、`material_id`、`qty`、`price_incl_tax`、`tax_rate`、`amount`、`tax_amount`、`total_amount`、`invoiced_qty`。

唯一：`uk_source_line(ar_type, source_line_id)`（保证同一出货行只生成一次应收，事件重复投递时幂等）。

### fin_sales_invoice 销项发票登记（编码规则 FIN_SALES_INVOICE）

| 字段 | 类型 | 说明 |
|---|---|---|
| customer_id | id | |
| invoice_type | enum(VAT_SPECIAL/VAT_NORMAL/EXPORT/OTHER) | 专票 / 普票 / 出口发票 / 其他 |
| invoice_no | str(64) | 发票号码（税务系统开出后录入） |
| invoice_date | date | |
| currency | str(3) | |
| amount / tax_amount / total_amount | amt | |
| lines | 关联表 fin_sales_invoice_line | 应收单行 ID、开票数量、金额 |
| invoice_status | enum(REGISTERED/VOIDED/RED) | 已登记 / 作废 / 红冲 |

本系统只做**开票登记**（记录已开发票与应收的对应关系），不直接对接税控开票系统（P2）。

## 3. 页面

### 3.1 应收单列表（T1）

查询：单号、客户、类型、状态、业务日期（默认本月）、来源单号、订单号、是否已核销（全部/未核销/部分/已核销）、是否已开票、到期日（范围）、仅逾期。
列：单号、类型（红字单金额红色）、客户、来源单号（链接）、业务日期、币别、价税合计、本位币、已核销、未核销、已开票、到期日（逾期红）、状态、操作。
底部合计（本位币）。
工具栏：[新建其他应收]、[批量确认]、[开票登记]（勾选同一客户已确认应收）、[导出]。

### 3.2 应收单详情（T5）

按钮：确认（草稿，`fin:receivable:confirm`）、反确认（已确认，未核销、未开票、未生成凭证，原因）、作废（草稿）、开票登记、打印。
页签：明细、核销记录、发票记录、凭证、操作日志。

### 3.3 其他应收（T4）

单头：客户*、币别*、汇率、业务日期*、到期日、说明*、附件；明细：项目说明*、金额*、税率（默认 0）。提交按审批流（FIN_OTHER_RECEIVABLE）→ 已确认。

### 3.4 开票登记（T4）

选择客户已确认、未完全开票的应收单行（可部分开票），录入发票类型*、发票号码*、开票日期*；明细开票数量（≤ 未开票数量），金额自动计算（可调整尾差 ≤ 1 元）。保存后回写应收单 invoiced_amount、行 invoiced_qty，发布 `InvoiceIssuedEvent`（销售订单已开票数量）。

## 4. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| FIN-AR-R01 | 事件 | 监听 `ShipmentConfirmedEvent`：按出货单生成应收（草稿；参数自动确认时直接已确认）；补货订单（金额 0）不生成 | — |
| FIN-AR-R02 | 事件 | 监听 `ShipmentReversedEvent`：对应应收为草稿/已确认未核销未开票 → 作废；否则该事件不应发生（出库反确认时已被 FIN-AR-R07 阻止） | — |
| FIN-AR-R03 | 事件 | 监听 `SalesReturnReceivedEvent`：生成红字应收（按原订单单价 × 退货数量，负数） | — |
| FIN-AR-R04 | 事件 | 监听 `ComplaintClaimAgreedEvent`：生成折让红字应收（负数，可核销到该客户的蓝字应收） | — |
| FIN-AR-R05 | 确认 | 业务日期所在会计期间未结账 | `会计期间 {period} 已结账` |
| FIN-AR-R06 | 确认/作废/核销 | 发布 `ReceivableBalanceChangedEvent(customerId)`（CRM 信用） | — |
| FIN-AR-R07 | 同步校验 | 监听 `StockOutReversingEvent`（销售出库）：对应应收已核销或已开票时抛出异常阻止 | `该出货已开票/已收款核销，不能反确认` |
| FIN-AR-R08 | 开票 | 开票数量 ≤ 未开票数量；同一发票号码不重复 | `发票号码「{no}」已登记` |
| FIN-AR-R09 | 到期日 | 按订单付款条件的出货类节点计算（出货日 / 提单日 / 月结）；提单日期回填后重算 | — |

## 5. 接口

`/finance/receivables`（列表、详情、confirm、unconfirm、void、export）、`POST /finance/receivables/other`、`POST /finance/receivables/batch-confirm`、`/finance/sales-invoices`（CRUD、void）。

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| FIN-AR-T01 | 出货 4,000 USD，汇率 7.12 | 出库确认 | 生成应收 4,000 USD / 28,480 CNY |
| FIN-AR-T02 | 同一出货事件重复投递 | — | 不重复生成（唯一约束） |
| FIN-AR-T03 | 退货退款 50 × 10 USD | 退货入库确认 | 红字应收 −500 USD |
| FIN-AR-T04 | 应收已核销 | 仓库反确认出库 | 提示不能反确认 |
| FIN-AR-T05 | 开票 3 行中的 2 行 | 开票登记 | 应收已开票金额增加；销售订单行已开票数量回写 |
