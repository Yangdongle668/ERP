# 08-03 入库单

## 1. 功能说明

所有入库都通过入库单完成。入库单有两种来源：

1. **业务生成**：上游业务单据通过 `InventoryDocApi.createStockIn` 生成草稿入库单，仓管员核对实物后“确认入库”；
2. **手工新建**：只有“其他入库”可以手工新建。

- 使用者：仓管员
- 优先级：P0

### 1.1 入库类型

| 入库类型 | 编码 | 来源单据 | 允许的入库仓 | 数量可改 | 成本 |
|---|---|---|---|---|---|
| 采购入库 | PURCHASE_IN | 资材·到货单 | 需检物料：待检仓；免检物料：物料默认仓（可用仓） | 否 | 采购价 |
| 委外入库 | OUTSOURCE_IN | 资材·委外单收货 | 同采购入库 | 否 | 加工费 + 月末材料成本 |
| 生产入库 | PRODUCTION_IN | 生产·生产订单完工入库 | 需 FQC：待检仓；否则：半成品仓 / 成品仓 | 否 | 月末计算 |
| 生产退料入库 | PRODUCTION_RETURN | 生产·退料单 | 良品退料：可用仓；不良退料：不良品仓 | 否 | 月末计算 |
| 销售退货入库 | SALES_RETURN | 销售·销售退货单 | 退货仓 | 否 | 原出库成本 |
| 其他入库 | OTHER_IN | 手工 | 可用仓、不良品仓 | 是 | 录入单价 |
| 盘盈入库 | COUNT_GAIN | 仓库·盘点单 | 盘点仓库 | 否（系统生成并自动确认） | 参考单价 |
| 期初入库 | OPENING | 仓库·期初导入 | 任意仓库 | 否（系统生成并自动确认） | 导入单价 |

“数量可改 = 否”的入库单，仓管员只能补充库位、批次属性、序列号；实物数量与单据不符时使用“退回”，由来源单据处理（例如到货单反审核后重新登记）。

## 2. 数据表

### inv_stock_in 入库单头（BaseDocDO，编码规则 INV_STOCK_IN）

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| in_type | enum(PURCHASE_IN/OUTSOURCE_IN/PRODUCTION_IN/PRODUCTION_RETURN/SALES_RETURN/OTHER_IN/COUNT_GAIN/OPENING) | 是 | | |
| warehouse_id | id | 是 | | 入库仓（一张单一个仓） |
| supplier_id | id | 否 | | 采购/委外入库时由来源带出 |
| customer_id | id | 否 | | 销售退货时 |
| reason | dict(inv_other_in_reason) | 条件 | | 其他入库必填 |
| confirmed_by / confirmed_at | id / datetime | 否 | | 确认人、确认时间 |
| reject_reason | str(256) | 否 | | 退回原因 |

`source_type` / `source_id` / `source_no` 记录来源业务单据；`doc_date` 为业务日期（确认时默认为当天，可改为不早于来源单据日期的日期）。

状态：草稿 DRAFT → （仅其他入库：待审批 PENDING_APPROVAL → 已审核 APPROVED）→ 已入库 COMPLETED；草稿可作废（手工）或退回（业务生成，结果为 VOIDED 并通知来源）。

## 4. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| INV-IN-R01 | 生成 | `createStockIn` 请求必须包含来源单据类型、ID、行 ID；同一来源行不能被两张未作废的入库单同时引用 | `来源单据行已生成入库单「{no}」` |
| INV-IN-R02 | 生成 | 仓库由来源模块指定，或按规则计算（需检 → 默认待检仓；免检 → 物料默认仓） | — |
| INV-IN-R03 | 保存/确认 | 入库仓必须符合 1.1 的仓库约束 | `{入库类型}只能入【{允许的仓库类型}】` |
| INV-IN-R04 | 确认 | 库位、批次、生产日期、序列号按物料属性必填（见 02 过账规则） | `第 {n} 行：{字段}不能为空` |
| INV-IN-R05 | 确认 | 过账成功后状态为已入库，发布 `StockInConfirmedEvent`（来源类型、来源 ID、每行 source_line_id 与基本单位数量、批次） | — |
| INV-IN-R06 | 退回 | 退回原因必填；单据作废并发布 `StockDocRejectedEvent`，来源模块提醒来源单据经办人 | `请填写退回原因` |
| INV-IN-R07 | 反确认 | 期间未结账；冲销后库存不为负；来源模块同步校验（监听 `StockInReversingEvent`，可抛出异常阻止，例如采购入库已对账、生产入库已被领用） | 来源模块提示原文，或 `入库的物料已被使用，不能反确认…` |
| INV-IN-R08 | 反确认 | 成功后状态回到草稿（业务生成）或已审核（手工），发布 `StockInReversedEvent`，来源模块扣回已入库数量 | — |
| INV-IN-R09 | 来源撤销 | 来源单据反审核时调用 `cancelBySource`：未确认的入库单作废；已确认的阻止来源反审核 | `已生成的入库单「{no}」已入库，请先反确认` |
| INV-IN-R10 | 自动确认 | 参数 `inv.in.auto-confirm-source` 为是且所有必填信息齐全时，生成后自动确认（确认人记为系统，操作人为来源单据审核人） | — |
| INV-IN-R11 | 日期 | 单据日期不早于来源单据日期、不晚于今天 | `入库日期不能早于来源单据日期 {date}` |

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| INV-IN-T01 | 到货单含需检物料 A 1000、免检辅料 B 50 | 到货单审核 | 生成 2 张入库单：A → 待检仓，B → 辅料仓，状态“待入库” |
| INV-IN-T02 | A 批次管理 | 仓管员不填批次直接确认 | 自动生成批次号 B260924001，过账成功；到货单的已入库数量回写 1000 |
| INV-IN-T03 | 仓库启用库位 | 未填库位确认 | 提示“第 1 行：库位不能为空” |
| INV-IN-T04 | 实物只到 900 | 仓管员退回（原因“实收 900”） | 入库单作废；资材到货单经办人收到提醒 |
| INV-IN-T05 | 其他入库选择待检仓 | 保存 | 提示“其他入库只能入【可用仓、不良品仓】” |
| INV-IN-T06 | 采购入库已被领用 | 反确认 | 提示“入库的物料已被使用，不能反确认…” |
| INV-IN-T07 | 已入库的采购入库单 | 到货单反审核 | 提示“已生成的入库单「IN-…」已入库，请先反确认” |
| INV-IN-T08 | 其他入库配置了审批流（金额 > 1 万） | 提交 2 万的其他入库 | 进入待审批；审批通过后状态“已审核”，仓管员确认后入库 |
