# 08-02 库存模型与过账

## 1. 功能说明

本文定义库存的数据模型、可用量口径、过账引擎（入库、出库、冲销）和成本口径。它是仓库模块的后端核心，入库单、出库单、调拨单、盘点都通过它改变库存。

- 优先级：P0
- 本文没有独立页面（库存查询见 08-库存查询与报表）。

## 2. 数据表

### inv_stock 库存余额

库存的最小粒度（库存维度）：**物料 + 仓库 + 库位 + 批次**。

| warehouse_id | id | 是 | | |

| batch_no | str(64) | 是 | '' | 不管理批次时为空字符串 |
| qty | qty | 是 | 0 | 现存量（基本单位） |
| last_in_date | date | 否 | | 最近入库日期 |
| last_out_date | date | 否 | | 最近出库日期 |

## 3. 可用量口径（全系统统一）

```
现存量 = Σ inv_stock.qty（指定范围）
可用现存量 = Σ inv_stock.qty，条件：仓库为可用仓 且 仓库启用 且 批次未冻结 且 批次未过期
可用量 = 可用现存量 − Σ 有效预留（qty − released_qty）
```

- 待检仓、不良品仓、退货仓的库存计入**现存量**，不计入**可用量**。
- `InventoryQueryApi.getAvailableQty(materialId)` 返回全部可用仓的可用量；传入 warehouseId 时只算该仓。

## 4. 过账引擎

### 4.1 入口

仓库模块内部的 `StockPostingService`（实现 `InventoryApi.post / reverse`），只由入库单、出库单、调拨单、盘点单的“确认”动作调用。**其他模块不直接调用过账**，而是通过 `InventoryDocApi` 生成仓库单据。

### 4.2 过账步骤（在调用方事务内执行）

1. **期间校验**：业务日期所在期间未结账（INV-PST-R01）。
2. **幂等校验**：同一仓库单据（doc_type + doc_id）不能重复过账（R02）。
3. **行校验**：物料启用、仓库启用、库位（启用库位管理的仓库必填）、批次（批次管理物料必填）、序列号（序列号管理物料必填，个数 = 数量）、数量 > 0 且符合单位精度。
4. **排序加锁**：按 (material_id, warehouse_id, location_id, batch_no) 排序后逐行处理，避免并发死锁。
5. **入库行**：
   - 批次管理物料：批次档案不存在则创建（见 07-批次与序列号），存在则校验物料一致；
   - `INSERT … ON DUPLICATE KEY UPDATE qty = qty + ?`（或先查后更新，带乐观锁重试 3 次）；
   - 写流水，balance_qty 为更新后余额。
6. **出库行**：
   - 条件更新：`UPDATE inv_stock SET qty = qty − ?, version = version + 1 WHERE id = ? AND qty >= ?`；影响 0 行时报库存不足（R04）；允许负库存时不带 `qty >= ?` 条件；
   - 出库批次必须未冻结、未过期（R05）；出库仓必须符合单据类型的仓库约束（见各单据文档）；
   - 写流水。
7. **序列号**：入库时序列号状态置为“在库”并记录仓库；出库时校验状态为“在库”且在该仓库，置为“已出库”。
8. **预留释放**：出库行带有预留来源时同时释放对应预留。
9. **事件**：事务内发布 `StockChangedEvent`（物料 ID 列表，供预警等 AFTER_COMMIT 监听）。

### 4.3 冲销（反确认）

`reverse(docType, docId)`：对该单据的每条原流水生成方向相反、数量相同的流水（`is_reversal=1`），库存反向变动。冲销入库时同样要校验库存足够（已被领用的入库不能冲销，R06）。

## 5. 成本口径

| 流水 | unit_cost 来源 |
|---|---|
| 采购入库 | 采购订单不含税单价 × 汇率（折算为本位币）÷ 单位换算 |
| 委外入库 | 材料成本在月末计算，加工费取委外单不含税单价；过账时先记加工费部分 |
| 生产入库、生产退料入库 | 过账时为空，月末成本计算后回填 |
| 销售退货入库 | 按原出库成本（原出库流水已计算成本时），否则月末计算 |
| 其他入库、盘盈 | 单据上录入的单价；为空时取该物料上期末加权平均单价，再没有取标准成本 |
| 所有出库、盘亏 | 过账时为空，月末按**月加权平均**回填（财务模块成本计算） |
| 调拨 | 调出、调入流水同成本，不影响物料总成本 |

**库存金额参考值**（库存查询中显示，字段权限 `inv:stock:cost`）= 数量 × 参考单价；参考单价 = 最近一个已结账期间的期末加权平均单价，没有时取最近一次入库单价。

## 6. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| INV-PST-R01 | 过账 | 业务日期所在库存期间已结账 | `库存期间 {period} 已结账，不能过账` |
| INV-PST-R02 | 过账 | 同一单据不能重复过账 | `单据「{no}」已过账，不能重复过账` |
| INV-PST-R03 | 过账 | 批次管理物料必须有批次号；序列号管理物料序列号个数必须等于数量 | `物料「{code}」需要填写批次号` / `物料「{code}」序列号数量 {n} 与数量 {qty} 不一致` |
| INV-PST-R04 | 出库 | 库存不足（不允许负库存时） | `物料「{code}」在仓库「{wh}」{批次 {batch}}库存不足，需要 {need}，现存 {have}` |
| INV-PST-R05 | 出库 | 冻结批次、过期批次不能出库（报废出库、退供应商出库、检验调拨除外） | `批次「{batch}」已冻结，不能出库` / `批次「{batch}」已过期（{date}），不能出库` |
| INV-PST-R06 | 冲销 | 冲销入库时库存必须足够 | `入库的物料已被使用，不能反确认：物料「{code}」现存 {have}，需要冲回 {need}` |
| INV-PST-R07 | 并发 | 乐观锁冲突自动重试 3 次，仍失败则提示 | `库存数据繁忙，请稍后重试` |
| INV-PST-R08 | 序列号 | 入库序列号不能是“在库”状态；出库序列号必须在该仓库在库 | `序列号「{sn}」已在库` / `序列号「{sn}」不在仓库「{wh}」` |
| INV-PST-R09 | 精度 | 数量按物料基本单位精度，超过精度拒绝 | `物料「{code}」数量精度不能超过 {n} 位小数` |

## 7. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| INV-PST-T01 | 物料 A 在 W-RAW 批次 B1 有 100 | 两个请求并发各出库 60 | 一个成功，一个提示库存不足；余额 40，流水两条（一入一出） |
| INV-PST-T02 | A 在 W-QC 有 50、W-RAW 有 100 | 查询可用量 | 现存量 150，可用量 100 |
| INV-PST-T03 | B1 冻结 | 生产领料出库 B1 | 提示“批次「B1」已冻结，不能出库” |
| INV-PST-T04 | 入库 100 后已领用 80 | 反确认该入库单 | 提示“入库的物料已被使用，不能反确认…现存 20，需要冲回 100” |
| INV-PST-T05 | 9 月已结账 | 确认业务日期为 9-30 的出库单 | 提示“库存期间 202609 已结账，不能过账” |
| INV-PST-T06 | 同一出库单在两个页签同时确认 | — | 只过账一次；第二次提示“单据已过账” |
| INV-PST-T07 | 序列号物料数量 3 | 只录 2 个序列号确认 | 提示序列号数量不一致 |
