# 09-04 报工

## 1. 功能说明

记录每道工序的产出：合格数、不良数、报废数、工时、人员、设备/工装。报工驱动工序进度、生产订单完工数量、倒冲扣料、IPQC 检验、工装寿命、成本工时。

- 使用者：班组长、操作员
- 优先级：P0

## 2. 数据表

### mfg_report 报工单（BaseDocDO，编码规则 MFG_REPORT）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| prod_order_id | id | 是 | |
| operation_seq | int | 是 | 工序号（报工点） |
| work_order_id | id | 条件 | 参数要求时必填 |
| work_center_id | id | 是 | |
| report_date | date | 是 | 生产日期 |
| shift | dict(mfg_shift) | 是 | |
| good_qty | qty | 是 | 合格数 ≥ 0 |
| defect_qty | qty | 是 | 不良数（待处理，可返修）≥ 0 |
| scrap_qty | qty | 是 | 报废数 ≥ 0 |
| scrap_reason | dict(mfg_scrap_reason) | 条件 | 报废 > 0 必填 |
| work_hours | rate | 是 | 实际工时（人·小时，合计） |
| machine_hours | rate | 否 | 设备工时 |
| tooling_id | id | 否 | 使用的工装 |
| start_time / end_time | datetime | 否 | |
| report_status | enum(DRAFT/APPROVED) | 是 | 草稿 / 已审核（参数自动审核时直接已审核） |

### mfg_report_operator 报工人员

`report_id`、`user_id`（或 `operator_name`，未开账号的操作员）、`hours`。

## 3. 页面

### 3.1 快速报工（专用页面，适配车间电脑/平板）

路由 `/production/report/quick`。

```
┌ 快速报工 ──────────────────────────────────────────────────┐
│ 扫描工单/流程卡条码：[__________________]（或选择生产订单+工序） │
│ ─────────────────────────────────────────────────────────── │
│ MO-202609-0012  FG1 控制板   工序 30 组装   工单 WO-…-003     │
│ 派工 300   已报 120   本工序可报 180（上道合格 300）            │
│ 合格 [   ]   不良 [   ]   报废 [   ] 报废原因 [▾]            │
│ 工时 [   ]h  人员 [张三 × 李四 ×] [+]   工装 [M-001 ▾]         │
│ 不良明细：[+ 登记不良]（不良代码、数量、描述）                    │
│                                     [提交报工（Ctrl+Enter）]   │
└────────────────────────────────────────────────────────────┘
```

- 输入框大字号（18px），数字输入支持触屏数字键盘。
- 扫码后自动带出工单信息，光标定位到“合格”。
- 提交成功后清空，光标回到扫码框，上方显示“已报工：合格 150”。
- 不良数 > 0 时必须登记不良明细（不良代码合计 = 不良数 + 报废数中因不良报废的部分，见 06）。

### 3.2 报工单列表（T1）

查询：单号、生产订单、产品、工序、工作中心、日期（默认今天）、班次、人员、状态。
列：单号、日期、班次、生产订单、产品、工序、工作中心、合格、不良、报废、良率、工时、标准工时（= 合格 × 标准秒 ÷ 3600）、效率（标准 ÷ 实际）、人员、工装、状态、操作（审核、反审核、编辑、删除）。
工具栏：[新建报工]（T4 表单形式，字段同快速报工）、[批量审核]。

## 4. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| MFG-RPT-R01 | 保存 | 生产订单为已下达/生产中（未暂停）；工序为报工点 | `生产订单已暂停` / `工序 {seq} 不是报工点` |
| MFG-RPT-R02 | 保存 | 本工序累计（合格 + 不良 + 报废）≤ 上一报工点累计合格数（含不良返修后转合格的数量）；首道报工点 ≤ 订单数量 × (1 + 超产比例) | `本工序可报数量为 {qty}` |
| MFG-RPT-R03 | 保存 | 报工日期不晚于今天、不早于生产订单下达日期 | — |
| MFG-RPT-R04 | 保存 | 工装：`ToolingApi.validateUsable`；适用物料包含本产品（不包含时警告） | 研发工程提示原文 |
| MFG-RPT-R05 | 审核 | 更新工序和工单数量；非报工点工序随下一报工点自动完成（数量同步）；末道报工点合格数累加到订单 completed_qty；报废累加 scrapped_qty；执行倒冲（见 03 R05）；发布 `WorkReportApprovedEvent`（研发工程累加工装次数、财务工时）；工序为检验点时发布 `IpqcTriggerEvent`；首次报工订单进入生产中 | — |
| MFG-RPT-R06 | 反审核 | 下一报工点的累计合格仍 ≤ 本工序反审核后的合格数；末道工序反审核后 completed_qty ≥ 已申请完工入库数量；冲回倒冲出库；发布 `WorkReportReversedEvent` | `下道工序已报工，不能反审核` / `已申请完工入库，不能反审核` |
| MFG-RPT-R07 | 不良处理 | 不良数进入“待处理不良”，在不良登记中处理为返修（返修后可再次报合格）或报废（见 06） | — |
| MFG-RPT-R08 | 工时 | 工时 > 0；人员工时合计 = 工时（多人时）；工时超过（班次时长 × 人数）时警告 | — |

## 5. 接口

`/production/reports`（CRUD、approve、unapprove、batch-approve）、`GET /production/reports/context?barcode=`（扫码解析工单/订单并返回可报数量）、`GET /production/reports/context?prodOrderId=&seq=`。

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| MFG-RPT-T01 | 工序 10 合格 300 | 工序 20 报合格 310 | 提示“本工序可报数量为 300” |
| MFG-RPT-T02 | 末道工序报合格 90、报废 2 | 审核 | 订单完工 90、报废 2；倒冲执行；工装次数增加 |
| MFG-RPT-T03 | 工序 20 为检验点 | 报工审核 | 品质生成 IPQC 检验单 |
| MFG-RPT-T04 | 工序 30 已报工 | 反审核工序 20 使其合格少于工序 30 已报 | 提示“下道工序已报工，不能反审核” |
| MFG-RPT-T05 | 快速报工扫描流程卡 | — | 自动带出订单工序和可报数量 |
