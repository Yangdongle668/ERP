# 04-07 回款跟踪

## 1. 功能说明

订单审核时按付款条件生成**回款计划**（如 30% 定金、70% 见提单），随出货、提单等事件计算到期日，财务收款分配到订单后更新已收金额。业务员据此催收，管理层查看回款情况。

- 回款的账务处理（收款单、核销）在财务模块；本功能只做计划与跟踪。
- 使用者：业务员、业务主管、财务
- 优先级：P0

## 2. 数据表

### sal_payment_plan 回款计划

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| order_id | id | 是 | |
| seq | int | 是 | 节点顺序（来自付款条件） |
| node_name | str(32) | 是 | 如“定金”“尾款” |
| percent | pct | 是 | |
| base_event | enum(...) | 是 | 同付款条件节点 |
| days | int | 是 | |
| plan_amount | amt | 是 | 计划金额（原币）= 订单价税合计 × 比例（最后一个节点补尾差） |
| event_date | date | 否 | 起算事件实际发生日期（下单日立即有；出货日/提单日由出货模块事件回写） |
| due_date | date | 否 | 到期日 = 事件日期 + 天数（或月末 + 天数） |
| received_amount | amt | 是 | 已收金额（原币） |
| plan_status | enum(NOT_DUE/DUE/OVERDUE/PARTIAL/RECEIVED) | 是 | 未到期 / 已到期 / 逾期 / 部分收款 / 已收齐（系统计算） |
| remark | str(256) | 否 | 催收备注 |

> 分批出货时，出货类节点按每次出货金额比例拆分为多条计划（如尾款 70% 的节点，第一次出货 40% 的货 → 生成“尾款-第 1 批”金额 = 该次出货金额 × 70%）。

## 3. 生成与更新规则

| 时点 | 处理 |
|---|---|
| 订单审核 | 按付款条件快照生成节点；ORDER_DATE 节点立即计算到期日；BEFORE_SHIPMENT 节点到期日 = 最早承诺交期（无则要求交期） |
| 出货确认（`ShipmentConfirmedEvent`） | SHIPMENT / BL_DATE / INVOICE_DATE / MONTH_END 类节点：按本次出货金额拆分出本批计划；SHIPMENT 和 MONTH_END 立即计算到期日 |
| 提单日期回填（`BillOfLadingReceivedEvent`） | BL_DATE 类本批计划计算到期日 |
| 开票（`InvoiceIssuedEvent`） | INVOICE_DATE 类计算到期日 |
| 收款分配（`ReceiptAllocatedEvent(orderId, amount)`） | 按节点顺序（先到期先分配）累加 received_amount；退款或核销冲回时反向扣减 |
| 订单变更 | 未收款的节点按新金额重算；已部分收款的节点保留已收，差额调整到最后一个未收齐节点 |
| 订单关闭 | 未出货部分对应的出货类计划金额取消（不再催收） |
| 每天 00:20 | 重算状态：到期日 < 今天且未收齐 → 逾期 |

## 4. 页面

### 4.1 回款计划（T1）

路由 `/sales/payment-plan`。以**计划节点**为单位。

查询：客户、订单号、业务员、状态（默认未收齐）、到期日期（范围）、仅逾期。
顶部汇总卡片：本月到期金额、已逾期金额、本月已收金额（本位币折算）。
列：订单号（链接）、客户、业务员、节点、比例、计划金额（币别 + 金额）、到期日（逾期红色，显示逾期天数）、已收、未收、状态、催收备注、操作（[记录催收]：备注 + 客户承诺付款日期）。
导出。

### 4.2 订单详情“回款计划”页签

同样的列，外加汇总：订单价税合计、已收、未收、预收（尚未出货但已收的金额）。

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| SAL-PP-R01 | 回款计划由系统生成与维护，用户只能录入催收备注，不能直接修改金额和到期日 |
| SAL-PP-R02 | BEFORE_SHIPMENT 节点未收齐时，出货通知保存时提示“订单 {no} 的出货前款项尚未收齐（未收 {amount}）”（警告，是否阻止由出货参数决定） |
| SAL-PP-R03 | 逾期计划每周一 09:00 汇总提醒业务员和业务主管 |
| SAL-PP-R04 | 补货订单（金额 0）不生成回款计划 |

## 6. 接口

`GET /sales/payment-plans`、`GET /sales/orders/{id}/payment-plans`、`POST /sales/payment-plans/{id}/follow-up`；`SalesOrderQueryApi.getUnpaidBeforeShipment(orderId)`（出货模块使用）。

## 7. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| SAL-PP-T01 | 订单 10,000 USD，TT30-70BL | 审核 | 定金 3,000 到期日 = 下单日；尾款 7,000 待出货 |
| SAL-PP-T02 | 财务收款 3,000 分配到订单 | — | 定金已收齐 |
| SAL-PP-T03 | 出货 40%（4,000） | 出货确认 | 生成“尾款-第 1 批”2,800，到期日待提单 |
| SAL-PP-T04 | 回填提单日期 10-10 | — | 第 1 批到期日 10-10 |
| SAL-PP-T05 | 10-11 仍未收 | 次日 | 状态逾期，逾期 1 天 |
