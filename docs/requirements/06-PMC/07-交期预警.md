# 06-07 交期预警

## 1. 功能说明

对未完成的销售订单行，比较承诺交期（无则要求交期）与**预计可出货日期**，提前发现可能延期的订单，分级预警给计划员和业务员。

- 使用者：计划员、业务员、PMC 主管
- 优先级：P1

## 2. 预计可出货日期计算（每天 06:00 和每次 MRP/排产后计算）

对每个未出完的订单行（未出货数量 Q）：

1. 成品可用库存按“承诺交期先后”分配给订单行，被满足的部分预计可出货日期 = 今天；
2. 剩余部分查找关联的生产订单（来源该订单行，或同产品按计划完工先后分配）：预计日期 = 生产订单预计完工（有排产结果取排产完工，否则计划完工；若生产订单缺料且预计齐套日期晚于计划开工，则顺延：齐套日期 + 生产提前期）+ 1 天（入库检验和出货准备，参数 P2）；
3. 仍有剩余（没有生产订单覆盖）：预计日期 = 今天 + 产品累计提前期（最长采购提前期 + 生产提前期）；
4. 延期天数 = 预计日期 − 承诺交期（> 0 为延期）。

## 3. 数据表

### pmc_delivery_alert

| 字段 | 类型 | 说明 |
|---|---|---|
| order_line_id | id | |
| order_no / customer_id / material_id | | 快照便于查询 |
| open_qty | qty | 未出货 |
| promised_date | date | |
| estimated_date | date | |
| delay_days | int | |
| alert_level | enum(INFO/WARNING/CRITICAL) | 按参数阈值：≤2 天 INFO、3～7 WARNING、>7 CRITICAL |
| cause | enum(NO_STOCK_NO_WO/MATERIAL_SHORTAGE/CAPACITY/WO_DELAY) | 原因：无库存无生产订单 / 缺料 / 产能（排产延期）/ 生产进度延误 |
| cause_detail | str(512) | 如“缺料：螺丝 316，PO-… 预计 10-05” |
| handle_status | enum(OPEN/HANDLED/IGNORED) | |
| handle_remark | str(512) | |
| calculated_at | datetime | |

同一订单行只保留一条当前预警（每次计算更新）；延期消除时自动关闭。

## 4. 页面（T1）

路由 `/pmc/alert`。顶部卡片：严重、警告、提示的数量。
查询：级别、原因、客户、业务员、物料、处理状态（默认未处理）。
列：级别（红/橙/蓝）、订单号（链接）、客户、物料、未出货、承诺交期、预计日期、延期天数、原因、原因说明、业务员、计划员、处理状态、操作（[处理]：填写处理说明（如“已与客户沟通延期至 10-15”）、可选 [调整承诺交期]（跳转交期回复）；[忽略]：原因）。

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| PMC-ALT-R01 | 新产生或级别升高的预警发布 `DeliveryAlertRaisedEvent`：工作台预警给计划员和该订单业务员；CRITICAL 同时通知 PMC 主管 |
| PMC-ALT-R02 | 已处理的预警，若延期天数继续增加超过 3 天，重新变为未处理 |
| PMC-ALT-R03 | 业务员只看到自己订单的预警（数据权限按销售订单业务员） |

## 6. 接口

`GET /pmc/delivery-alerts`、`POST /pmc/delivery-alerts/recalculate`、`POST /pmc/delivery-alerts/{id}/handle`、`/ignore`；`PmcQueryApi.getEstimatedDate(orderLineId)`（销售订单详情显示预计日期）。

## 7. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| PMC-ALT-T01 | 订单承诺 10-10，生产订单计划完工 10-15 | 计算 | 延期 6 天（+1 天准备），警告，原因“生产进度” |
| PMC-ALT-T02 | 成品库存足够 | 计算 | 无预警 |
| PMC-ALT-T03 | 延期 10 天 | — | 严重预警，PMC 主管收到通知 |
