# 06-01 需求池与交期回复

## 1. 功能说明

- **需求池**：把所有独立需求汇集到一处，是 MPS/MRP 的输入。需求池由事件自动维护，计划员一般不需要手工操作（可补充手工需求）。
- **交期回复**：销售订单审核后，计划员根据库存、在制、物料和产能情况回复每行的承诺交期，写回销售订单。

- 使用者：计划员
- 优先级：P0

## 2. 数据表

### pmc_demand 需求池

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| demand_type | enum(SALES_ORDER/FORECAST/SAFETY_STOCK/MANUAL) | 是 | |
| source_id / source_line_id / source_no | | 条件 | 销售订单行、预测行 |
| customer_id | id | 否 | |
| material_id | id | 是 | |
| qty | qty | 是 | 需求数量（基本单位），随来源变化更新 |
| fulfilled_qty | qty | 是 | 已满足（销售订单：已出货；预测：已冲销） |
| open_qty | qty | 是 | 未满足 = qty − fulfilled_qty |
| required_date | date | 是 | 需求日期：销售订单取承诺交期，无则要求交期；预测取该月 1 日（参数可改为月末）；安全库存为当天 |
| priority | int | 是 | 5；手工可设 |
| demand_status | enum(OPEN/CLOSED) | 是 | open_qty = 0 或来源关闭时 CLOSED |
| remark | str(256) | 否 | 手工需求说明 |

索引：`idx_material_date(material_id, required_date)`、`uk_source(demand_type, source_line_id)`。

## 3. 需求池维护规则

| 事件 | 处理 |
|---|---|
| `SalesOrderApprovedEvent` | 每个订单行插入一条 SALES_ORDER 需求（补货订单也计入；样品订单计入） |
| `SalesOrderChangedEvent` | 更新数量、日期；取消的行关闭 |
| `SalesOrderClosedEvent`、`SalesOrderUnapprovedEvent` | 关闭/删除对应需求 |
| `ShipmentConfirmedEvent` | 更新 fulfilled_qty |
| 承诺交期回复 | required_date 改为承诺交期 |
| `ForecastPublishedEvent` 及冲销变化 | 按净预测维护 FORECAST 需求（每个预测行一条） |
| 物料安全库存 | MRP 运算时临时计算（不落需求池） |

每天 01:30 全量对账：以销售订单、预测的实际数据重建需求池中未关闭的需求，防止事件丢失。

## 4. 页面

### 4.1 需求池（T1）

查询：物料、客户、需求类型、需求日期（默认今天起 90 天）、只看未满足（默认是）、计划员。
列：需求类型（标签）、来源单号（链接）、客户、物料编码、名称、规格、需求数量、已满足、未满足、需求日期、要求交期/承诺交期（订单）、可用库存、在制数量、在途采购（成品为委外）、优先级、状态。
工具栏：[新增手工需求]（物料*、数量*、需求日期*、说明*）、[导出]、[运行 MRP]（跳转 MRP 运算并带入范围）。

### 4.2 交期回复（专用）

路由 `/pmc/delivery-reply`。列出已审核、尚无承诺交期（或客户要求交期变更后需重新回复）的销售订单行。

| 列 | 说明 |
|---|---|
| 订单号 / 客户 / 业务员 | |
| 物料 / 规格 | |
| 数量 / 要求交期 | |
| 可用库存（成品） | 实时 |
| 在制（生产订单未完工） | 实时 |
| 物料齐套情况 | [分析] 按钮：对该产品 × 数量做单层 BOM 齐套（库存 + 在途到货日期），显示最晚齐套日期 |
| 建议交期 | 系统计算（R03），灰色显示 |
| 承诺交期 | 日期框（默认建议交期），可批量设置 |
| 回复说明 | 输入框 |

工具栏：[保存回复]（勾选行，写回销售订单）、[按建议回复]。

## 5. 业务规则

| 编号 | 规则 | 提示原文 |
|---|---|---|
| PMC-DMD-R01 | 手工需求必须填写说明；手工需求可修改、关闭 | `请填写需求说明` |
| PMC-DMD-R02 | 承诺交期不能早于今天 | `承诺交期不能早于今天` |
| PMC-DMD-R03 | 建议交期：可用库存（未被更早需求占用）≥ 订单数量 → 今天 + 1 天（出货准备）；否则 max(物料最晚齐套日期, 今天) + 产品生产提前期（含工艺固定时间）+ 1 天 | — |
| PMC-DMD-R04 | 保存回复调用 `SalesOrderApi.updatePromisedDate`；承诺交期晚于要求交期时销售自动标记交期风险 | — |
| PMC-DMD-R05 | 销售订单变更了要求交期或数量后，该行重新出现在交期回复列表（标记“需重新回复”） | — |

## 6. 接口

`GET /pmc/demands`、`POST /pmc/demands`（手工）、`PUT /pmc/demands/{id}`、`POST /pmc/demands/{id}/close`、`GET /pmc/delivery-replies/pending`、`POST /pmc/delivery-replies`、`POST /pmc/delivery-replies/kit-analysis`。

## 7. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| PMC-DMD-T01 | 订单 FG1 1000 审核 | — | 需求池出现 1000，需求日期 = 要求交期 |
| PMC-DMD-T02 | 出货 400 | — | 需求已满足 400、未满足 600 |
| PMC-DMD-T03 | 成品可用 1200 | 交期回复该订单 | 建议交期 = 明天 |
| PMC-DMD-T04 | 可用 0，物料最晚齐套 10-05，生产提前期 3 天 | 交期回复 | 建议交期 10-09 |
| PMC-DMD-T05 | 保存承诺交期晚于要求交期 | — | 销售订单显示交期风险，业务员收到通知 |
