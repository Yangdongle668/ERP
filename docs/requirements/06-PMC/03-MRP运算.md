# 06-03 MRP 运算

## 1. 功能说明

根据独立需求、BOM、库存、在途和在制，逐层计算每个物料的净需求，并按批量规则和提前期生成采购、生产、委外建议，以及对已有供应（订单）的例外信息。

- 使用者：计划员
- 优先级：P0

## 3. 计算逻辑

### 3.1 数据准备（一次性批量读取，避免逐行查询）

| 数据 | 来源 |
|---|---|
| 物料及计划属性、低位码 | 研发工程 `MaterialApi`（批量） |
| 默认 BOM（多级） | 研发工程 `BomApi` |
| 可用库存 | 仓库：可用仓合格未冻结库存 − 预留（按物料汇总） |
| 在途采购 | 资材：已审核订单行未到货数量 + 到货待检数量（在待检仓，视为即将可用，日期为今天 + 1），日期取确认交期/要求交期 |
| 在制 | 生产：已下达生产订单剩余数量（计划 − 合格入库 − 报废），日期取计划完工 |
| 在制分配 | 生产：已下达生产订单用料的未领数量，日期取计划开工（这是对子件的已分配需求） |
| 委外 | 资材：委外单未收货数量 |
| 独立需求 | 需求池（或 MPS）；安全库存 |

### 3.2 逐物料计算（按低位码从 0 开始逐层）

```
对每个物料，按日期排序合并：
  需求 = 独立需求 + 上层计划订单的相关需求（父件建议数量 × 用量 × (1+损耗)，日期 = 父件下达日期）+ 在制分配
  供给 = 可用库存（第 0 天）+ 在途采购 + 在制 + 委外

  逐日推进：
    预计可用 = 上日预计可用 + 当日供给 − 当日需求
    若 预计可用 < 安全库存（参数开启时，否则 < 0）：
       净需求 = 安全库存 − 预计可用
       【重排假设】先在展望期内查找当日之后、尚未被使用的已有供应（在途采购/在制/委外），
         按日期由近到远把它们视为“提前到当日”参与抵扣，并对每一笔产生 EXPEDITE 例外；
         抵扣后仍有净需求时才生成新的计划订单：
       按批量规则得到计划订单数量 Q：
         按需：Q = 净需求
         固定批量：Q = ⌈净需求 ÷ 固定批量⌉ × 固定批量
         按周期：合并从当日起 period_days 天内的全部净需求
         然后：Q = max(Q, MOQ)；MPQ > 0 时 Q = ⌈Q ÷ MPQ⌉ × MPQ
       生成计划订单（数量 Q，需求日期 = 当日，下达日期 = 当日 − 提前期）
       预计可用 += Q
```

- 取得方式 → 建议类型：采购 → PURCHASE；自制 → MAKE；委外 → OUTSOURCE。
- MAKE、OUTSOURCE 的计划订单按 BOM 展开为子件的相关需求（虚拟件透过，子件直接挂到虚拟件的父件上）。
- 生产提前期：自制件提前期（天）；有工艺路线时可选按“准备 + 数量 × 标准工时 ÷ 日产能”计算（P2）。
- 替代料（参数开启）：主料在某日出现净需求时，先用替代料的可用库存（按替代比例）抵扣，再生成主料建议。
- **例外信息**：对已有供应（在途采购、在制、委外），若其日期晚于第一次需要它的日期超过容差 → EXPEDITE；早于需要日期超过容差 → DEFER；整个展望期内该供应都未被用到 → CANCEL；供应日期 < 今天且仍未到 → PAST_DUE。

### 3.3 运算控制

- 同一时间只允许一个运算（分布式锁：数据库锁记录 `pmc_mrp_run` 中 RUNNING 状态），第二个请求提示“MRP 正在运算中（{runNo}，{operator} 发起于 {time}）”。
- 运算以后台任务执行（任务中心可见进度）；完成后通知发起人。
- 新运算成功后，上一次运算中状态为“待处理”的建议全部置为 SUPERSEDED；已转单、已忽略的不受影响。
- 运算失败（如发现 BOM 循环、层数超限）：记录失败原因（指出物料），不影响上一次运算的建议。
- 运算期间业务单据可正常操作，数据以运算开始时读取的快照为准。

## 4. 页面

### 4.1 MRP 运算（T1 + 运算弹窗）

路由 `/pmc/mrp`。

**运算弹窗**：运算类型*（全量 / 净变更 / 指定订单）、指定订单（多选销售订单行）、展望期（天）、包含预测、包含安全库存、使用替代料（默认取参数）→ [开始运算]。

**运算记录列表**：运算号、类型、状态（运行中显示进度）、开始/结束时间、耗时、物料数、建议数、发起人、失败原因、操作（[查看建议]、[查看例外]）。

### 4.2 供需平衡（专用）

路由 `/pmc/mrp/balance`。选择物料（和运算记录）→ 按日期列出：日期、类型（期初库存 / 需求：订单/预测/父件需求/在制分配 / 供给：在途/在制/委外/计划订单）、单号、需求数量、供给数量、预计结存（< 安全库存橙色、< 0 红色）。点击父件需求可跳转父件的供需平衡。用于计划员解释建议来源。

## 5. 业务规则

| 编号 | 规则 | 提示原文 |
|---|---|---|
| PMC-MRP-R01 | 同时只能有一个运算 | `MRP 正在运算中（{runNo}，{operator} 发起于 {time}）` |
| PMC-MRP-R02 | BOM 循环或层数超限时运算失败并指出物料 | `MRP 运算失败：物料「{code}」的 BOM 存在循环引用` |
| PMC-MRP-R03 | 停用物料不产生建议（其需求记录为例外“物料已停用”） | — |
| PMC-MRP-R04 | 运算服务重启导致中断：RUNNING 超过 1 小时的运算自动置为 FAILED（原因“运算中断”） | — |
| PMC-MRP-R05 | 性能：1 万物料、5 层 BOM 全量运算 ≤ 5 分钟（内存计算，批量读取，批量写入结果） | — |

## 6. 接口

`POST /pmc/mrp/runs`（发起）、`GET /pmc/mrp/runs`、`GET /pmc/mrp/runs/{id}`、`GET /pmc/mrp/balance?materialId=&runId=`。
