# 03-03 信用管理

## 1. 功能说明

为客户设置信用额度，在销售订单审核、出货单提交时检查信用占用，超额时警告或阻止，降低坏账风险。

- 使用者：财务（设置额度）、业务主管（申请调整）
- 优先级：P1

### 1.1 信用占用口径（本位币）

```
已用额度 = 应收余额（财务：未核销应收 − 未核销预收）
         + 未出货订单金额（销售：已审核未关闭订单的 未出货数量 × 含税单价 × 汇率）
可用额度 = 信用额度 − 已用额度
```

检查时：新单据金额（本位币含税）与可用额度比较。出货单检查时，本次出货对应的订单金额已包含在“未出货订单金额”中，因此出货检查只比较 **应收余额 + 本次出货金额 − 该订单已预收** 与额度（避免重复计算）。

另外，**逾期应收**（超过到期日未收）> 0 时，按控制方式同样警告或阻止（参数化，默认检查）。

## 2. 数据表

### crm_customer_credit 信用占用（技术表，由事件更新）

| 字段 | 类型 | 说明 |
|---|---|---|
| customer_id | id 主键 | |
| receivable_balance | amt | 应收余额（本位币） |
| overdue_amount | amt | 逾期应收（本位币） |
| open_order_amount | amt | 未出货订单金额（本位币含税） |
| updated_at | datetime | |

每天 01:00 全量重算一次（调用财务、销售查询接口），防止事件丢失造成偏差。

### crm_credit_change 信用额度调整单（BaseDocDO，单号 = 客户编码-yyyyMMddHHmm）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| customer_id | id | 是 | |
| old_limit | amt | 是 | 原额度（系统带出） |
| new_limit | amt | 是 | 新额度，≥ 0 |
| old_days / new_days | int | 否 | 信用期 |
| old_control / new_control | enum(DEFAULT/NONE/WARN/BLOCK) | 否 | 控制方式 |
| expire_date | date | 否 | 临时额度到期日：到期后自动恢复为 old_limit |
| reason | str(512) | 是 | |

状态：草稿 → 待审批 → 已审核（生效）；可作废。

## 3. 页面

### 3.1 客户信用（T1）

路由 `/crm/credit`，权限 `crm:credit:query`。

查询：客户、负责人、使用率（全部 / ≥80% / ≥100%）、有逾期（开关）。
列：客户编码、简称、负责人、控制方式、信用额度、应收余额、逾期应收（>0 红色）、未出货订单、已用额度、可用额度（<0 红色）、使用率（进度条）、信用期、更新时间、操作（[调整额度]、[调整记录]）。

### 3.2 调整额度（T2 中弹窗，生成调整单）

字段：客户（只读）、当前额度（只读）、新额度*、当前信用期/新信用期、控制方式、临时额度（开关）+ 到期日、原因*。
提交后按审批流（CRM_CREDIT_CHANGE）审批，审核后更新客户的 credit_limit、credit_days、credit_control。

### 3.3 调整记录

抽屉：该客户所有调整单（日期、原额度 → 新额度、原因、状态、审批人）。

## 4. 业务规则

| 编号 | 触发 | 规则 | 提示原文 |
|---|---|---|---|
| CRM-CRD-R01 | 检查 | 控制方式 NONE：不检查；WARN：返回 pass=true + 提示，由调用方显示警告（订单审核时审核人可继续）；BLOCK：返回 pass=false，调用方阻止 | `客户「{name}」信用额度不足：额度 {limit}，已用 {used}，本次 {amount}，超出 {over}` |
| CRM-CRD-R02 | 检查 | 未设置信用额度（为空）的客户：视为不控制额度，但仍检查逾期 | — |
| CRM-CRD-R03 | 检查 | 逾期应收 > 0 且控制方式为 BLOCK 时阻止 | `客户「{name}」有逾期应收 {amount}，请先催收` |
| CRM-CRD-R04 | 调整 | 新额度生效后记录操作日志；临时额度到期日次日 00:30 自动恢复原额度并通知负责业务员 | — |
| CRM-CRD-R05 | 事件 | 监听 `ReceivableBalanceChangedEvent`（财务）和 `SalesOrderOpenAmountChangedEvent`（销售）增量更新占用 | — |
| CRM-CRD-R06 | 检查时点 | 由参数 `crm.credit.check-points` 决定销售订单审核、出货单提交是否检查 | — |

## 5. 接口

`GET /crm/credits`、`GET /crm/credits/{customerId}`、`POST /crm/credit-changes`、`/{id}/submit`、`GET /crm/credit-changes?customerId=`；Java `CreditApi.check(customerId, amountBase, checkPoint)`。

## 6. 验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|
| CRM-CRD-T01 | 额度 100 万，应收 60 万，未出货订单 30 万，控制 BLOCK | 审核 20 万新订单 | 阻止，提示超出 10 万 |
| CRM-CRD-T02 | 同上，控制 WARN | 审核 | 弹出警告，审核人可确认继续 |
| CRM-CRD-T03 | 有逾期 5 万，BLOCK | 审核订单 | 提示“有逾期应收 50,000.00，请先催收” |
| CRM-CRD-T04 | 临时额度 150 万到 10-31 | 11-01 | 自动恢复为 100 万并通知业务员 |
| CRM-CRD-T05 | 收款核销 10 万 | — | 应收余额减少 10 万，可用额度增加 |
