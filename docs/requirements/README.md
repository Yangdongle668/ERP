# 需求文档编写约定与阅读说明

## 1. 文档结构

```
docs/requirements/
├── 00-总体需求与通用规范.md        全局规则：单据、状态、编码、审批、单位、币别、权限、审计……
├── 01-系统管理/                    每个模块一个目录
│   ├── README.md                   模块概述、页面清单、角色、分期、对外接口汇总
│   ├── 01-组织架构.md               每个功能点一个文件
│   └── ...
├── 02-工作台/
└── ...
```

每个功能点文件固定包含以下章节（没有内容的章节写“无”，不能删）：

1. **功能说明**：做什么、谁用、优先级
2. **数据表**：字段级定义
3. **页面**：页面模板、查询条件、列表列、按钮、表单字段
4. **状态与流转**（有状态的对象）
5. **业务规则**：编号、规则、错误提示原文
6. **接口**：路径、方法、权限
7. **与其他模块的交互**（有则写）
8. **验收用例**

## 2. 数据表写法

### 2.1 公共字段（不在各表中重复列出）

所有表都包含 `BaseDO` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键，雪花 ID |
| version | int | 乐观锁 |
| created_by / updated_by | bigint | 创建人 / 修改人 |
| created_at / updated_at | datetime | 创建时间 / 修改时间 |
| deleted | tinyint | 逻辑删除 |

业务单据**单头**另外包含 `BaseDocDO` 字段：`doc_no`（单号）、`doc_date`（单据日期）、`status`（单据状态）、`org_id`、`dept_id`、`owner_id`（经办人）、`source_type` / `source_id` / `source_no`（来源单据）、`remark`。

标注“（技术表）”的表不含公共字段，按其自身定义。

### 2.2 类型记法

| 记法 | 数据库类型 | 说明 |
|---|---|---|
| `id` | bigint | 引用其他表的 ID |
| `str(n)` | varchar(n) | |
| `text` | text | 长文本 |
| `int` | int | |
| `qty` | decimal(18,4) | 数量 |
| `amt` | decimal(18,2) | 金额 |
| `price` | decimal(18,6) | 单价 |
| `rate` | decimal(18,6) | 汇率、比例、系数 |
| `pct` | decimal(7,4) | 百分比，存 0.1250 表示 12.50% |
| `date` | date | |
| `datetime` | datetime | |
| `bool` | tinyint(1) | 0/1 |
| `enum(A/B/C)` | varchar(32) | 存枚举名 |
| `dict(xxx)` | varchar(32) | 存数据字典 `xxx` 的项值 |
| `json` | text（存 JSON） | 仅用于不需要查询的结构化数据 |

表格列：**字段 | 类型 | 必填 | 默认 | 说明**。“必填”指数据库非空。唯一约束和索引在表下方单独列出。

## 3. 页面写法

- 页面模板代号（T1～T8）和公共组件名见《[UI 设计规范](../ui/UI设计规范.md)》，模板的通用行为不再重复。
- **查询条件**表：条件 | 控件 | 匹配方式 | 默认值
- **列表列**表：列 | 字段 | 宽度 | 对齐/格式 | 说明（可排序、链接等）
- **按钮**表：按钮 | 位置 | 权限 | 显示条件 | 行为
- **表单字段**表：字段 | 控件 | 必填 | 默认 | 可编辑 | 校验与说明
  - “可编辑”写“始终” / “仅新建” / “仅草稿” / “否（系统生成）”等
- 控件名：输入框、数字框、文本域、下拉（固定选项）、`DictSelect(字典)`、`MaterialSelect` 等公共组件、日期、日期范围、开关、单选、复选、树选择、上传。

## 4. 业务规则写法

规则编号：`<模块缩写>-<功能缩写>-R<序号>`，如 `SYS-USR-R03`。每条规则写明**触发时机**和**不满足时的提示原文**：

> **SYS-USR-R03** 保存时：用户名全局唯一（不区分大小写）。
> 提示：`用户名「{username}」已存在`

提示原文就是后端 `BizException` 的消息，开发时直接使用，错误码由开发者在模块号段内分配。

## 5. 接口写法

接口表：**方法 | 路径 | 权限 | 说明**。路径省略统一前缀 `/api`。请求/响应字段与“表单字段”“列表列”一致，不再重复定义，特殊结构另行说明。

## 6. 验收用例写法

用例编号：`<模块缩写>-<功能缩写>-T<序号>`。格式：**前置条件 → 操作 → 预期结果**。每条业务规则至少对应一条验收用例；开发完成的标准是全部验收用例通过，且其中的核心用例已写成自动化集成测试。

## 8. 优先级

- **P0**：一期必须上线；**P1**：本模块开发时一并完成；**P2**：后续版本，文档中只描述范围，不做字段级定义。
