# 14 系统备份（总览）

## 1. 模块定位

为**超级管理员**（拥有 `*` 权限的账号，如 `admin`）提供系统级的数据保护：一次备份全部数据（所有模块的数据库表 + 本地存储的附件文件），需要时**一键恢复**到备份时的状态。

边界：
- 本模块是"模块只能访问本模块表"规则的唯一例外：通过 JDBC 元数据枚举并导出 / 导入所有表，不写其他模块的表名，也不使用其他模块的实体；
- 只备份业务数据，不备份迁移历史（`flyway_history_*`）和本模块自己的表（`bak_*`），因此恢复不会抹掉备份记录与恢复记录；
- 不负责数据库服务器级的备份（binlog、物理备份），生产环境仍建议同时做数据库层面的定期备份。

## 2. 功能与页面清单

| 功能 | 页面 | 路由 | 菜单权限 | 优先级 |
|---|---|---|---|---|
| 备份与恢复 | 备份设置、备份记录、恢复记录 | `/backup/records` | `*`（仅超级管理员） | P1 |

所有接口（`/api/backup/**`）均要求 `*` 权限，普通角色即使被授予全部菜单权限也返回 403。

## 3. 备份

### 3.1 触发方式

| 类型 | 说明 |
|---|---|
| 手工（MANUAL） | 页面「立即备份」，可选择是否包含附件、填写说明 |
| 自动（AUTO） | 定时任务 `BAK_AUTO`（每天 03:15），参数 `bak.auto.enabled` 开启后执行 |
| 恢复前（PRE_RESTORE） | 每次恢复开始前自动备份当前数据，用于撤销恢复 |
| 上传（UPLOAD） | 上传之前下载的备份文件（.zip），用于迁移到新服务器或从异地备份恢复 |

同一时间只允许一个备份或恢复任务（R01）。备份在后台执行，期间系统可正常使用；备份是各表逐个导出，**不是**严格的时点一致快照，建议在业务空闲时（如夜间）执行。

### 3.2 备份文件格式

保存在 `erp.backup.path`（默认 `./data/backups`），文件名 `erp-backup-<yyyyMMdd-HHmmss>[-<类型>]-<随机后缀>.zip`：

```
manifest.json        格式 erp-backup/1、数据库类型、各模块数据版本（Flyway 版本）、表清单与行数、是否含附件、附件数
tables/<表名>.jsonl   第一行 {"columns":[...],"types":[...]}，之后每行一条记录（JSON 数组）
files/...            附件存储目录下的全部文件（仅 erp.file.storage=local 时）
```

记录 SHA-256 校验值，恢复前校验文件未被篡改或损坏。

### 3.3 保留策略

参数 `bak.auto.keep`（默认 7）：自动备份与恢复前备份各自只保留最近 N 份，更早的连同文件一起删除。手工与上传的备份不自动删除。

## 4. 一键恢复

### 4.1 恢复前检查（R02）

- 备份状态为成功，文件存在且 SHA-256 一致；
- 备份中每个模块的数据版本与当前系统**完全一致**（升级系统后，旧版本备份不能直接恢复，需先部署对应版本）；
- 备份中的表与列与当前数据库一致；
- 输入确认文字「确认恢复」。

### 4.2 恢复过程

1. 进入**维护模式**：除恢复进度查询和健康检查外，所有接口返回 503「系统维护中」，定时任务暂停；
2. 等待进行中的请求结束（`erp.backup.settle-millis`，默认 2 秒）；
3. 自动备份当前数据（恢复前备份）；
4. 在**一个数据库事务**中清空所有表并批量写入备份数据，任何错误整体回滚；
5. 如备份包含附件：解压到临时目录后替换附件目录；
6. 清空缓存，重新同步权限 / 字典 / 参数声明与定时任务，发布 `DataRestoredEvent` 供各模块刷新内存数据；
7. 退出维护模式。

恢复成功后当前登录全部失效，所有用户（包括超级管理员）需用**备份中的**账号密码重新登录。

### 4.3 失败处理

- 数据库阶段失败：事务回滚，数据保持恢复前状态；
- 附件阶段失败：数据库已恢复，可用"恢复前"备份再恢复一次回到原状态；
- 恢复记录保存在 `bak_restore_log`，页面「恢复记录」可查。

## 5. 参数与配置

| 参数 / 配置 | 默认 | 说明 |
|---|---|---|
| `bak.auto.enabled` | 否 | 是否每天自动备份 |
| `bak.auto.include-files` | 是 | 自动备份是否包含附件 |
| `bak.auto.keep` | 7 | 自动 / 恢复前备份保留份数 |
| `erp.backup.path` | `./data/backups` | 备份目录（Docker 部署请挂载到数据卷） |
| `erp.backup.settle-millis` | 2000 | 进入维护模式后等待请求结束的毫秒数 |

## 6. 数据表

bak_record（备份记录）、bak_restore_log（恢复记录）。

## 7. 错误码（1_014_xxx）

备份不存在、有任务进行中、备份文件缺失、备份未成功、文件格式无效、数据版本不一致、表结构不一致、未输入确认文字、校验值不一致、备份失败、恢复失败。
